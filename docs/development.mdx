## Clone the repository

```bash
git clone https://github.com/DataFog/datafog-core.git
cd datafog-core
```

## Rust quality gates

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
```

## Cross-SDK verification

Use the repository verifier to check toolchain pins, build the bindings and exercise the installed packages.

```bash
cargo dfv doctor
cargo dfv build
cargo dfv check
cargo dfv smoke
cargo dfv parity --live
```

Run `cargo dfv check --models` for model changes. Each run writes a report under `target/dfv/runs/`.

## Documentation preview

The Mintlify content root is `docs/`.

```bash
npm install --global mint
cd docs
mint validate
mint broken-links --check-anchors
mint dev --no-open
```

`mint dev --no-open` starts a local preview without opening a browser.

## Repository structure

```text
crates/core/        Rust scanning and transformation engine
bindings/python/    Python extension
bindings/node/      Node.js native binding
bindings/wasm/      Browser WebAssembly binding
fixtures/           Shared conformance fixtures
docs/               Architecture records and Mintlify documentation
```

## Publish a release from GitHub Actions

Qualify the release commit and publish the base SDKs and companion packages in dependency order. Push each runtime tag separately. If publication stops partway through, check the registry versions and completed workflow runs before retrying. The [publication runbook](https://github.com/DataFog/datafog-core/blob/main/docs/core-v1-publication.md) covers qualification, tag handling, companion workflows and installed-package checks.

### npm trusted publisher setup

Configure [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/)
once in each package's npm settings. Use GitHub organization **DataFog**,
repository **datafog-core**, environment **npm**, and allow direct
`npm publish`:

| Packages | Workflow filename |
| --- | --- |
| `@datafog/node`, `@datafog/node-darwin-arm64`, `@datafog/node-linux-x64-gnu`, `@datafog/node-linux-arm64-gnu`, `@datafog/node-win32-x64-msvc` | `publish-node.yml` |
| `@datafog/wasm` | `publish-wasm.yml` |

The publish jobs request GitHub's OIDC identity with `id-token: write` and use
npm 11.17.0 on Node 24. They do not use `NPM_TOKEN` or a local machine's npm
session. npm generates provenance for these public packages automatically.

The Node workflow builds four native binaries (macOS ARM64, Linux x64/ARM64
and Windows x64), transfers the generated
JavaScript loader and types to the publish job, and runs the installed-package
suite against the assembled package and its Linux native dependency before
publishing. The WASM workflow runs the browser package suite before publishing.

Intel macOS publication and qualification jobs are removed after 1.6.0. Future
Python releases have nine wheels plus a source distribution; Node has four
native platform packages plus its root package. Existing Intel artifacts and
historical release tags remain available.
