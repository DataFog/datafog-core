**Status: prepared and unpublished. Publication is on hold pending explicit
release authorization.** The commands below target the future 1.7.0 packages;
they are not registry installation instructions for an available release.
No release date has been assigned.

Published Core 1.5.0 and the latest published release,
[Core 1.6.0](https://github.com/DataFog/datafog-core/releases/tag/v1.6.0), contain
the [EMAIL boundary regression tracked in #266](https://github.com/DataFog/datafog-core/issues/266).
The prepared 1.7.0 source includes the fixes in [#267](https://github.com/DataFog/datafog-core/pull/267) and [#270](https://github.com/DataFog/datafog-core/pull/270), which also restores PHONE findings after a digit and separator that 1.5.0 and 1.6.0 drop.
Consumers waiting for this fix need to adopt 1.7.0 after publication. Version
constraints such as `<1.7`, including those in MCP consumers, exclude it and
must be updated to admit the fixed release.

## Changes from 1.6.0

- Recover EMAIL findings after surrounding source dots and field delimiters,
  including `carol@example.com.|alice@example.com` and `said "ok".alice@example.com`.
  ENV/SQL mailbox punctuation and original-source offsets are preserved.
- Report an EMAIL that directly follows one or more dots, in text, ENV and SQL
  formats, restoring 1.4.0 coverage ([#270](https://github.com/DataFog/datafog-core/pull/270)):
  `see [1].alice@example.com`, `me...alice@example.com` and
  `KEY=".alice@example.com"` find `alice@example.com`. This replaces the 1.5.0
  malformed-local rejection: `bob..x@example.com` is reported as
  `x@example.com`, and the text before the dots is not covered by the span.
- Report a PHONE directly after a digit and comma whenever it passes phone
  validation, and after a digit and dot when it has `+`, parentheses or another
  separator, so CSV rows with a numeric column are found again
  (`2,+1-202-555-0143`, `1,34,2025550143`, `7,+1.2025550143`). PHONE is matched
  on each line separately, so a number at a line end is no longer dropped when
  the next line starts with a digit. Unsigned single-dot decimals after a digit
  and comma (`6,306.2723362`) and unseparated or dotted runs after a digit and
  dot (`2.202.555.0143`) are not reported. Accepted false positives and the
  exact line-break rules are listed in the
  [changelog](https://github.com/DataFog/datafog-core/blob/main/CHANGELOG.md).
- Retire Intel macOS qualification and prebuilt SDK publication. Python omits
  its Intel macOS wheel; Node omits `@datafog/node-darwin-x64`. Existing 1.6.0
  Intel archives remain available. Intel source builds are outside maintained CI.
  Dropping a platform is a minor release under the [versioning policy](https://github.com/DataFog/datafog-core/blob/main/VERSIONING.md).
- Correct the documented Linux glibc requirement for the native Python companion:
  the qualified 1.6.0 `datafog-fogvault` wheel requires glibc 2.38, while base
  `datafog-core` GNU wheels use a glibc 2.28 baseline. Check the final 1.7.0
  candidate wheel tags before publication.

Workspace contract 1, marker syntax and existing snapshot formats are unchanged
from 1.6.0. Application vaults, literal denylists and Python mapping retirement
were introduced in [1.6.0](/releases/1-6-0).

## Prepared coordinated package set

All 15 Core-owned distributions are prepared at **1.7.0**:

| Registry | Packages | Planned archives |
| --- | --- | --- |
| crates.io | `datafog-core`, `datafog-fogvault-migration`, `datafog-fogvault-native` | 3 crates |
| PyPI | `datafog-core` | 9 wheels plus source distribution |
| PyPI | `datafog-fogvault` | 3 native wheels |
| npm | `@datafog/node`, four native platform packages, `@datafog/wasm`, `@datafog/core-fogvault-browser`, `@datafog/core-fogvault-legacy-browser`, `@datafog/core-sqlite-browser`, `@datafog/core-fogvault-node` | 10 tarballs |

The planned set has **26 archives**. Base Node targets macOS ARM64, Linux
x64/ARM64 GNU and Windows x64. Base Python targets Linux x64/ARM64 GNU and
musl, Linux s390x/ppc64le, macOS ARM64 and Windows x64/ARM64. The optional native
Node/Python companions retain macOS ARM64, Linux x64 GNU and Windows x64.
Independent FogVault engine packages remain 0.1.0. The `datafog` Python
application, MCP and browser extension keep their own release tracks.

After publication, the prepared installation commands will be:

```sh
python -m pip install datafog-core==1.7.0 datafog-fogvault==1.7.0
npm install --save-exact @datafog/node@1.7.0 @datafog/wasm@1.7.0
cargo add datafog-core@=1.7.0
```

## Qualification still required

The final versioned main commit must pass ordinary CI, the exact-commit
Core/FogVault gate's 19 required scopes, and all 12 required native model checks
(three backends on Linux x64/ARM64, macOS ARM64 and Windows x64). Preparing this
page or updating versions does not establish that evidence.

Publication remains on hold. Do not create runtime publication tags, run actual
publish workflows or create the consolidated GitHub release before authorization
and final candidate qualification. Verify the complete public archive set
against retained publication inputs before announcing a coordinated release.
